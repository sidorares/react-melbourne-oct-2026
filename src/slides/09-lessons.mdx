## What working with agents changed

<Grid cols={3} gap={32}>

<Card variant="top" tone="muted" title="Not like before">

Nine years: 4 PRs to react-x11. Since July: **2,287 PRs** across nine repos. The bottleneck moved from writing the code to deciding what to build and checking that it is right.

</Card>

<Card variant="top" tone="blue" title="Good DX is agent DX">

Errors that say what to change. Types that are the ground truth. A headless test that renders a PNG you can look at. What helps a newcomer helps an agent.

</Card>

<Card variant="top" tone="orange" title="Good architecture is guard rails">

Sharp contracts between layers: the host config, components on public elements only. Invariants pinned by tests, performance as CI gates. The rules written down, in the repo.

</Card>

</Grid>

<Notes>

Draft: say this in your own words, from your own experience. This is the answer to the question the Evolution slide raised: how does a project go from nine quiet years to 2,287 merged PRs since July? That is across nine repositories: react-x11 752, react-x11-components 799, ntk 399, dbus-native 107, node-x11 83, the windowkit backends (appkit 94, win32 16, wayland 7) and node-x11-dri 30. Before July, from April 2017 to June 2026, the same repositories merged 65 between them, and react-x11 itself 4. react-x11's AGENTS.md alone is 1,885 lines; ntk and react-x11-components have their own.

Not like before: compare it with how node-x11 and the 2015 prototype were written, by hand, evenings. What you do now is mostly deciding, reviewing and looking; the next lesson is the "looking" part.

Good DX: everything an agent needs is what a human newcomer needs, only more so. react-x11's AGENTS.md has a rule, "an error you hit is an error an app developer will hit": every error should say what was expected, what was found and what to change. The stack is written in a way an agent can verify alone: react-x11/test renders into an in-process X server and writes a PNG, which is also how the one-shot agents from the start of the talk are checking their apps right now.

Good architecture: with this much change going in, structure is what keeps it from turning into mush. Layers with small, sharp contracts (the host config; @react-x11/components may only use public host elements, and a missing hook becomes a core issue). Invariants pinned by tests (a blitted scroll is byte-identical to a full repaint). Performance as CI gates (frames painted for a window nobody can see). And pre-release, no backwards compatibility: a rename lands everywhere in one PR, because the agent does the tedious part.

</Notes>

## Tests and specs help a lot. They can't replace eyeballing

<Grid cols={3} gap={32}>

<Card variant="top" tone="orange" title="Green suite, 700× slower">

A shadow blur re-run on every composite. Requests, bytes, composites, area and the rendered pixels were all identical before and after the fix.

</Card>

<Card variant="top" tone="blue" title="Obvious once somebody looked">

Text 3 px low, a badge riding high, a header that never lined up with its table. Each one passed.

</Card>

<Card variant="top" title="So: gut feeling, and demos">

Hover it, drag it, resize it. The stress demo exists to be looked at.

</Card>

</Grid>

<Notes>

The blur bug was found by hovering a card and feeling the lag. No metric moved until a new one was added that counts convolved pixels. Every visual defect in the examples rework passed a green suite and was obvious the moment somebody looked.

</Notes>
