## React, rendered to native windows

<Cols template="1fr 600px" gap={64} align="stretch">
<Col gap={32}>

- Same React, same hooks. The host elements are **{'<window>'}**, **{'<box>'}**, **{'<text>'}**, **{'<image>'}**, **{'<canvas>'}**, **{'<textinput>'}**…
- Four backends: X11 (pure-JS protocol, works over the network), Cocoa, win32, Wayland
- Plus **@react-x11/components**: editors, terminal, maps, charts, 3D… an HTML engine
- No DOM, no browser, no Electron

```jsx
<window title="counter" width={240} height={120}>
  <box style={{ padding: 8, ':hover': {…} }}
       onClick={() => setN(n + 1)}>
    <text>+1</text>
  </box>
</window>
const root = await createRoot(); root.render(<Counter />);
```

</Col>
<Col justify="center" style={{ alignItems: 'center', background: 'var(--sand)', borderRadius: 16, padding: 24 }}>

<Shot src="img/tasks.png" alt="The react-x11 tasks example: a task list with a text input, filter buttons and checkboxes" width={546} height={520} />

</Col>
</Cols>

<Notes>

react-x11 is a renderer in the same sense react-dom and react-native are: React itself is unchanged, and what differs is what the host elements turn into. Here they are windows and painted boxes rather than DOM nodes.

The X11 backend speaks the protocol in pure JavaScript (node-x11), so an app can run on one machine and display on another, which is the flagship reason the project exists. Cocoa and win32 are the defaults on macOS and Windows.

The screenshot is the tasks example, rendered by the real renderer into node-x11's in-process X server (that is how the docs screenshots are generated, and how the tests run without a display).

</Notes>

## Step 1: one component, hot reloaded

<Cols template="1110px 1fr" gap={48}>
<Col gap={24}>

<Code size={26}>

```jsx
import React, { useState } from 'react';
import { Button } from 'react-x11';

export default function App() {
  const [n, setN] = useState(0);
  return (
    <box style={{ padding: 24, gap: 12, alignItems: 'center' }}>
      <text style={{ fontSize: 24 }}>You clicked {n} times</text>
      <Button onPress={() => setN(n + 1)}>Click me</Button>
    </box>
  );
}
```

</Code>

</Col>
<Col gap={24}>

<Shot src="img/app.png" alt="A react-x11 dev window: 'You clicked 3 times' above a 'Click me' button, on a dark grey background" width={480} height={300} />

<Code size={26} pad={24}>

```bash
$ npx react-x11 dev app.jsx
```

</Code>

<Small>No window, no `createRoot`: dev mounts the default export in a window of its own. Save, and it reloads with the count kept. The first run offers to install the hot-reload toolchain: say **Y**.</Small>

</Col>
</Cols>

<Notes>

The smallest react-x11 app there is: one file, one component, one export. Save it as app.jsx and run react-x11 dev on it.

Plain React: useState and a Button from react-x11's built-in widgets, with onPress. The host elements are box, a flexbox container, and text, the only place raw strings may go. Styles go in the style prop and mean what CSS means.

dev does the rest: it mounts the default export, and because the component renders no window, it puts it in one of its own. Change the label and save: Fast Refresh swaps the component and the count stays. On the first run it says it needs Babel and react-refresh, which are optional peer dependencies so apps don't ship them, and asks to install them; answer Y. Option-click the button and your editor opens at its line.

The screenshot is this file, rendered headlessly with dev's window around it, after three clicks.

</Notes>

## Step 2: your own window, <Mono>hello.jsx</Mono>

<Cols template="1030px 1fr" gap={40}>
<Col>

```jsx
import React from 'react';
import { createRoot } from 'react-x11';

function App() {
  return (
    <window title="hello" width={360} height={180}>
      <box style={{ flexGrow: 1,
        alignItems: 'center', justifyContent: 'center' }}>
        <text style={{ fontSize: 24 }}>hello from react-x11</text>
      </box>
    </window>
  );
}

const root = await createRoot();
root.render(<App />);
```

</Col>
<Col>

<Shot src="img/hello.png" alt="The hello window: 'hello from react-x11' centred on a dark grey background" width={540} height={270} />

<Code size={26}>

```bash
$ npm pkg set type=module
$ npm install -D tsx
$ npx tsx hello.jsx
```

</Code>

<Small>Or just `bun hello.jsx`. Only <O>{'<window>'}</O> is a real window; the rest is drawn into it.</Small>

</Col>
</Cols>

<Notes>

Step 2 is what an app looks like without dev: it opens its own window and mounts its own root. This is the shape a real app's entry file has.

Three host elements: window, box and text. A window is a real window of the operating system; box is a flexbox container laid out by yoga; text is a run of text, and raw strings are only allowed inside it.

Styles go in the style prop, never as flat props, and mostly mean what CSS means: flexGrow, alignItems, justifyContent. The window's width and height are props, not style, because they are the real window's geometry.

createRoot connects to whatever this machine has, Cocoa on a Mac and X11 elsewhere, and render mounts synchronously.

Running it needs two more commands. `npm pkg set type=module`, because the file calls `await createRoot()` at the top level, which needs an ES module, and npm init writes `"type": "commonjs"`; tsx then refuses with an error about top-level await and the cjs output format. And tsx itself, to run JSX on Node. Bun runs the .jsx file directly and does not care about either, so with Bun it is just `bun hello.jsx`. The screenshot is exactly this file, rendered headlessly; the dark background is the default theme following the desktop's dark mode.

</Notes>
