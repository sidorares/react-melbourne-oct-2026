## X11 in one slide

<Grid cols={2} gap={40}>

<Card variant="top" tone="blue" label="X client" title="Your app">

Sends requests over a socket: create a window, draw this, upload these glyphs. Gets events back: key, pointer, expose.

</Card>

<Card variant="top" tone="orange" label="X server" title="The display">

Owns the screen, the keyboard and the mouse. Draws what it is told. Can be **another machine**.

</Card>

</Grid>

- Network transparent: `ssh -X` and the window shows up on your laptop
- **node-x11**: the X11 wire protocol in pure JavaScript. No libX11, no native code
- **ntk**: the toolkit layer on top: windows, a canvas-like 2D context over XRender, fonts

<Notes>

Keep it to a minute. The point to land: your app is a network client of the display, even on a local socket. That is why every round trip and every byte is a cost, which comes back in the performance part.

Remote display is also why X11 is still the default backend on Linux, even with Wayland supported.

</Notes>

<Notes>

Issue #4: windows were created bottom-up, children before their parents, so everything had to be reparented and staged. The fix was to make no display calls in render at all, and to create windows top-down in the commit phase, each one naming its real parent from the start. Closed 26 July 2026.

After that it went fast. Each commit on master is a squash-merged PR, so the bars are roughly PRs per month.
