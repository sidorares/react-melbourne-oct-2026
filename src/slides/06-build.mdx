<Notes>

Pick up step 1's app.jsx, the one the audience ran at the start. Add a box with an onClick and a :hover and an :active block: that is a button of your own, and it counts. Hold the mouse down on it: it darkens before you release, because :hover and :active are repainted by the renderer, with no React render; the count changes on release, because that is when a click is.

Break it on purpose once (render a raw string outside a text) to show the error window, then fix and save. Click a few times, save an edit, and the count survives. ⌥-click the button to jump to the line. Hover a component in DevTools and it highlights in the real window.

Before the talk: check the react-x11 you demo includes the dev + DevTools default, and that react-devtools-core is installed in the demo folder.

## The AI-assisted developer experience

<Lead style={{ fontSize: 34 }}>react-x11 is younger than every model's training data. The library has to ship its own context.</Lead>

<Cols template="1fr 1fr" gap={56} align="start">

<Eyebrow tone="orange">Next: what would you want?</Eyebrow>

- **`npm create react-x11`**: AGENTS.md, DESIGN.md, a test, the dev script
- **Docs inside the package**, versioned with the code: a skill, not a website
- **"Copy as prompt"** in the dev error window
- **`react-x11 dev --mcp`**: the agent sees the tree, clicks, takes a screenshot
- **llms.txt** and "copy as Markdown" on the docs site

</Col>

<Notes>

The argument: react-x11 has had 752 merged PRs since July and renamed things freely before 2.0. No model was trained on it. Whatever an agent knows about react-x11, the project has to hand it, and it has to match the installed version, not last month's.

Already there: the oneshot folder is the proof. AGENTS.md says what react-x11 and the components are; DESIGN.md says how a Mac app should look. The agents running behind the deck have only those two files and npm. react-x11/test's toPNG is how they check their own work: an agent can't see a window, but it can read a PNG. And errors written as "what was expected, what was found, what to change" help an agent exactly as much as a person.

Next, none of which exists yet, so ask the room:
- `npm create react-x11` runs create-react-x11 (both that name and @react-x11/create are free on npm). The scaffold writes the agent files, a smoke test and a dev script, and removes the "type: module, install tsx" detour from step 2.
- Docs shipped in node_modules match the installed version, which a website and a model's memory don't.
- The error window already builds its text in one pure function (describeError); a "Copy as prompt" button adds the code frame, the component stack, the version and the backend.
- An MCP server in dev mode would be Playwright for native windows: the DevTools plumbing already holds the tree.

On the name: "Agent Experience (AX)" is Mathias Biilmann's term, from Netlify, early 2025; AIDX is ours for tonight. Check the attribution before saying it.

Questions for the room: where should agent docs live, the site, the package, or a skill registry? Should errors be written for people, or for agents that explain them to people? Is DESIGN.md the new design system?

Segue: everything so far, the dev command, the test harness, the stress demo, sits on code that did not exist in July. Back to issue #4.
